# 수원시 도서관 반응형 웹 서비스 PRD

## 1. 문서 개요

- 작성일: 2026-11-09
- 버전: 0.1 — 선택 화면 기반 초안
- 대상: 수원시 도서관의 모바일·데스크톱 웹 서비스
- 목적: 자료 탐색, 도서 상세 및 소장정보 확인, 인증, 상호대차 신청으로 이어지는 이용 경험을 정의한다.
- 근거: Figma 선택 영역의 화면 이미지, 레이어 구조, 텍스트. 실제 서비스 동작·연결·서버 정책은 검증하지 않았다.

### 근거와 요구사항 구분

- **[확인]** 선택 화면에서 직접 확인한 구성·문구·상태.
- **[제안]** 화면을 실제 서비스로 구현하기 위해 추가한 요구사항. 승인 전 확정 정책이 아니다.
- **[미정]** 화면만으로 판단할 수 없거나 운영·개발 협의가 필요한 항목.
- 우선순위 P0/P1은 작성 제안이며 확정된 출시 계획이 아니다.

## 3. 제품 목표와 사용자

### 목표 [제안]

1. 여러 도서관의 자료를 한곳에서 검색하고 소장 위치·이용 상태를 파악하게 한다.
2. 검색 결과에서 도서 상세 및 신청으로 이어지는 흐름을 명확하게 한다.
3. 모바일에서도 검색, 도서 발견, 방문 전 휴관일 확인을 쉽게 한다.
4. 신청 전 인증 필요성과 신청 결과를 분명하게 안내한다.

### 대상 사용자 [제안]

| 사용자           | 주요 과업                                          |
| ---------------- | -------------------------------------------------- |
| 비로그인 방문자  | 자료 검색, 도서 탐색, 로그인·회원가입 진입         |
| 회원             | 소장정보 확인, 이용 자격에 따른 예약·상호대차 신청 |
| 방문 예정 이용자 | 도서관 선택, 휴관일·자료 위치 확인                 |

회원과 정회원의 권한 차이, 신청 가능 등급은 [미정]이다.
정회원신청 표시만으로 로그인 상태나 자격을 단정하지 않는다.

## 4. 범위와 정보 구조

### 화면에서 확인된 범위 [확인]

- 홈: 검색, 인기검색어(데스크톱), 서비스 바로가기, 인기도서, 신착도서, 휴관일, 추천도서, 공통 푸터.
- 모바일 홈: 상단 햄버거 메뉴와 별도 홍보 배너 포함.
- 자료검색: 일반검색/상세검색 탭, 검색어, 도서관 선택, 자료 유형별 결과.
- 로그인: 아이디·비밀번호, 자동로그인, 수원시 통합회원 로그인 진입, 계정 찾기·회원가입.
- 도서 상세: 서지정보, 소개, 대출 상태, 소장정보·연관도서정보·통계정보 탭.
- 신청: 예약하기, 상호대차신청, 책나루 (무인)예약 진입과 상호대차 완료 알림.

### 링크·진입점만 확인된 범위

- 큐레이션
- 전자도서관
- 지역도서관 통합검색
- 나의도서관
- 희망도서 신청
- 통합예약신청
- 공지사항
- 서비스안내
- 경기도서관
- 도서관매거진
- 수원시 E-BOOK 자료관
- 디지털자료실 PC예약
- 열람실 좌석조회
- 도서관소개
- FACEBOOK

위 항목의 상세 화면·외부 연결 주소·업무 처리 절차는 본 초안의 확정 구현 범위에 포함하지 않는다.

### 추가 설계 또는 협의가 필요한 범위 [미정]

- 모바일 검색 결과·로그인·도서 상세·신청 완료 화면.
- 상세검색 필드, 연관도서정보·통계정보 탭 본문.
- 상호대차 수령관 선택, 신청 확인 단계, 예약·무인예약 완료 및 취소 흐름.
- 회원가입·계정 복구·정회원 신청 상세, 관리자 기능.

## 5. 핵심 사용자 흐름

아래 연결은 화면 구성을 토대로 정리한 [제안] 흐름이며 실제 동작 확인 결과가 아니다.

### A. 검색과 도서 상세

홈
→ 도서관 선택·검색어 입력
→ 자료검색 결과
→ 자료 유형/도서관 조건 확인
→ 도서 선택
→ 도서 상세
→ 소장정보 확인

### B. 비로그인 신청 진입

비로그인 검색 결과
→ 예약/로그인필요
→ 로그인 모달
→ 인증 성공
→ 기존 검색 맥락 복원
→ 사용자가 신청 의사를 다시 확인

인증 성공만으로 예약·상호대차가 자동 제출되지 않도록 제안한다.
인증 후 정확한 복귀 위치는 [미정]이다.

### C. 상호대차 신청

도서 상세
→ 소장도서관별 상호대차신청
→ 자격·자료 상태 재확인
→ 필요한 입력/확인 단계
→ 서버 처리 성공
→ “상호대차 신청이 완료되었습니다.” 알림
→ 확인 후 도서 상세 유지

신청 버튼과 완료 알림 사이의 입력 단계는 화면에 없으므로 필수 항목·단계 수는 [미정]이다.

### D. 모바일 도서 탐색·방문 준비

홈
→ 인기도서/신착도서/추천도서 탐색
→ 도서 선택 또는 더보기
→ 상세/목록 진입

홈
→ 휴관일에서 도서관·월 확인
→ 방문 일정 판단

## 6. 기능 요구사항

### FR-01. 공통 헤더·내비게이션 — P0 제안

- [확인] 로고, 로그인·회원가입 진입, 햄버거 메뉴가 있다.
- [확인] 데스크톱에는 자료검색·큐레이션·전자도서관·지역도서관 통합검색·나의도서관 메뉴가 있다.
- [제안] 로고로 홈에 접근하고, 주요 기능에 키보드와 터치로 접근할 수 있어야 한다.
- [미정] 메뉴 펼침 구조와 로그인 후 헤더, 로그아웃·세션 만료 표현.

**수용 기준**

- 각 메뉴의 목적지 또는 미지원 안내가 정의되어 있다.
- 모바일에서 주요 진입점이 누락되지 않는다.

### FR-02. 홈 검색 — P0 제안

- [확인] 도서관 선택, “검색어를 입력하세요.” 입력창, 검색 아이콘이 있다.
- [확인] 데스크톱에 인기검색어가 있다.
- [제안] 선택한 도서관과 검색어를 결과 화면에 전달하고 입력값을 유지한다.
- [제안] Enter 및 검색 버튼으로 제출할 수 있다.
- [미정] 기본 선택 도서관, 빈 검색어 처리, 검색 대상 필드, 인기검색어 집계 방식.

**수용 기준**

- 검색어와 도서관 조건이 결과 화면과 일치한다.
- 합의된 빈 입력 처리 정책이 적용된다.

### FR-03. 자료검색·필터 — P0 제안

- [확인] 일반검색·상세검색 탭, 검색 버튼, 도서관 체크박스 및 전체선택이 있다.
- [확인] 도서관 선택지는 다음과 같다.
  - 선경, 중앙, 창룡, 화서다산, 호매실, 서수원
  - 한림, 버드내, 북수원, 대추골, 일월, 광교홍재
  - 태장마루, 광교푸른숲, 매여울, 망포글빛
  - 슬기샘어린이, 지혜샘어린이, 바른샘어린이
  - 한아름, 반달어린이, 사랑샘, 희망샘, 인도래
- [확인] 자료 유형은 단행본·연속간행물·비도서·전자책이며 유형별 건수가 보인다.
- [제안] 전체선택은 개별 선택 상태와 일치해야 한다.
- [제안] 결과와 유형별 건수는 동일 검색 조건을 사용한다.
- [미정] 필터 즉시 적용/검색 시 적용, 모두 해제 시 동작, 정렬, 페이지 이동, 상세검색 필드.

**수용 기준**

- 도서관·자료 유형 변경 시 합의한 적용 방식대로 결과와 건수가 갱신된다.
- 결과 없음·조회 실패 상태가 구분된다.

### FR-04. 검색 결과 — P0 제안

- [확인] 표지, 소장도서관, 제목, 저자, 발행처, 발행년, 자료위치, 태그를 표시한다.
- [확인] 비로그인 화면에는 예약/로그인필요 버튼이 있다.
- [확인] 별도 결과 화면에는 대출불가, 타관대출 대기중, 예약자수 비율이 있다.
- [제안] 제목/표지 선택 시 해당 자료의 상세로 연결한다.
- [제안] 검색 목록 복귀 시 조건을 보존한다.
- [미정] 대출 상태의 비로그인 공개 범위.

서로 다른 화면만으로 회원에게만 상태를 공개한다고 확정하지 않는다.

**수용 기준**

- 동일 제목의 다른 저자·판본·소장자료를 구분할 수 있다.
- 선택한 자료와 상세 데이터가 일치한다.

### FR-05. 로그인 — P0 제안

- [확인] 검색 결과 위 배경 오버레이와 로그인 모달, 닫기 아이콘이 있다.
- [확인] 다음 항목을 제공한다.
  - 아이디·비밀번호 입력
  - 자동로그인
  - 로그인 버튼
  - 수원시 통합회원 로그인
  - 아이디/비밀번호 찾기
  - 회원가입
- [제안] 실패 원인을 안전하게 안내하고 비밀번호를 마스킹한다.
- [제안] 모달 종료 시 기존 검색 상태를 보존한다.
- [미정] 인증 제공자 연동 방식, 자동로그인 보존 기간, 실패 횟수 제한, 계정 찾기 주소.

**수용 기준**

- 필수값 누락·인증 실패·성공을 구분한다.
- 닫기와 키보드 접근이 가능하다.
- 인증 정보가 로그에 남지 않는다.

### FR-06. 도서 상세 — P0 제안

- [확인] 표지 및 서지정보, 미리보기·상세보기, 소개와 + 더보기, 대출 상태·예약자수를 표시한다.
- [확인] 소장정보·연관도서정보·통계정보 탭이 있다.
- [확인] 선택 화면의 본문은 소장정보이다.
- [제안] 소개 더보기로 생략된 내용을 읽을 수 있도록 한다.
- [미정] 미리보기/상세보기의 정확한 목적지 및 방식, 다른 탭의 데이터·집계 기준.

**수용 기준**

- 검색 결과와 서지 식별자가 일치한다.
- 소개·상태를 읽을 수 있다.
- 미정 탭은 본문을 정의하기 전 완료로 간주하지 않는다.

### FR-07. 소장정보·이용 신청 — P0 제안

- [확인] 소장도서관 수와 펼치기, 도서관별 자료실·대출 상태·일부 반납예정일을 표시한다.
- [확인] 예시 소장도서관은 서수원·한아름·태장마루이다.
- [확인] 각 행에 예약하기·상호대차신청·책나루 (무인)예약이 있다.
- [제안] 신청 가능 여부는 회원 자격과 해당 소장자료의 최신 서버 상태로 판단한다.
- [제안] 신청 불가 시 이유를 안내한다.
- [미정] 대출불가 사유별 신청 허용 규칙, 예약 정원, 중복 신청, 상호대차 대상관·수령관, 책나루 자격.

**수용 기준**

- 선택한 도서관의 소장자료에 정확히 신청한다.
- 화면의 회색 버튼 표현만으로 활성/비활성 정책을 결정하지 않는다.

### FR-08. 상호대차 완료 알림 — P0 제안

- [확인] 도서 상세 위 알림과 “상호대차 신청이 완료되었습니다.” 문구가 있다.
- [확인] 확인 버튼 및 닫기 아이콘이 있다.
- [제안] 서버 성공 응답 이후에만 완료를 표시한다.

- 모달은 작은 화면과 소프트 키보드 사용 중에도 입력 및 종료가 가능해야 한다.
- 지원 최소 폭, 브라우저 범위는 [미정]이다.

### 접근성

- WCAG 2.2 AA 수준을 목표로 협의한다.
- 입력 레이블을 제공한다.
- 검색·햄버거·닫기·화살표에 접근 가능한 이름을 제공한다.
- 키보드 탐색, 가시적 포커스, 모달 포커스 관리·복귀를 제공한다.
- 색상만으로 대출 상태·선택 상태를 구분하지 않는다.
- 글자 확대에서도 정보와 조작 수단을 유지한다.

### 보안

- HTTPS를 적용한다.
- 서버 측 인증·자격 검사를 수행한다.
- 안전한 세션 처리 및 상태 변경 요청 보호를 적용한다.
- 자동로그인 보안 정책은 별도 확정한다.

### 성능

- 도서 표지를 적정 크기로 제공한다.
- 화면 밖 이미지는 지연 로딩한다.
- 검색 응답 시간·웹 성능 수치 목표와 측정 환경은 출시 전 합의한다.

### 정합성

- 캐시된 상태를 신청 가능성의 최종 근거로 사용하지 않는다.
- 신청 처리 시 최신 상태를 재검사한다.

## 10. 검증 시나리오

1. 비로그인 사용자가 검색어·도서관을 설정하면 해당 조건의 결과와 유형별 건수를 확인할 수 있다.
2. 도서관 전체선택·개별 선택과 결과 조건이 일치한다.
3. 동일 제목의 다른 저자·판본을 구분하고 올바른 상세로 진입한다.
4. 비로그인 예약 진입 시 로그인 모달이 표시되고 닫은 뒤 검색 상태가 유지된다.
5. 로그인 실패·성공·세션 만료 상태를 구분하며 인증 성공만으로 신청이 제출되지 않는다.
6. 상세 화면의 서지·소장도서관·자료실·대출 상태가 동일 자료를 가리킨다.
7. 신청 시 자격과 최신 상태를 검사하고, 실패 시 성공 알림을 표시하지 않는다.
8. 상호대차 성공 시 지정 문구를 표시하고 확인 후 상세 화면을 유지한다.
9. 모바일 홈에서 검색·휴관일·큐레이션에 접근 가능하고 콘텐츠가 전역 가로 넘침 없이 표시된다.
10. 키보드로 검색·로그인·알림 확인을 수행하고 모달 종료 시 포커스가 복귀한다.
11. 추천도서의 제목·표지·소개가 일치하며 날짜·휴관일을 예시값으로 고정하지 않는다.

## 12. 확인이 필요한 사항과 콘텐츠 이슈

1. **추천도서 소개 불일치**
   - 모바일 및 데스크톱의 “오은영의 화해” 항목에 “여행자 - 하이델베르크” 소개가 들어 있다.
   - 오류를 요구사항으로 계승하지 않고 출처 확인 후 수정한다.

2. **예시 날짜**
   - 휴관일 2026.09, 반납예정일 2026/10/30·2026/11/06, 추석 안내 배너는 시안에 표시된 값이다.
   - 현재 운영 상태로 간주하거나 상수로 구현하지 않는다.

3. **예약 정원**
   - 자료별로 1/2, 2/2, 0/2, 1/1 등이 보인다.
   - 모든 도서의 정원이 2명이라고 단정할 수 없다.

4. **신청 자격**
   - 대출불가 상태에서 어떤 예약·상호대차·책나루 신청이 가능한지 확정해야 한다.

5. **인증과 공개 범위**
   - 상태 노출이 다른 검색 화면의 차이가 인증 정책인지 단순 시안 차이인지 확인해야 한다.

6. **일반/정회원**
   - 정회원신청과 통합회원 로그인의 관계, 회원 등급별 이용 권한을 확정해야 한다.

7. **모바일 범위**
   - 홈 외 핵심 화면의 모바일 설계와 중간 폭 동작이 필요하다.

8. **탭·링크**
   - 상세검색, 연관도서정보, 통계정보, 미리보기, 더보기 및 외부 서비스의 상세 동작·목적지를 정의해야 한다.

9. **운영 문구**
   - “도서관 사업부”·“수원시도서관사업소” 등 명칭 및 띄어쓰기·주소·약관의 공식 표기를 검토해야 한다.

10. **출시 승인**
    - 서비스 책임자, 일정, 연동 가용성, 우선순위, KPI 목표, 지원 기기 및 보안·접근성 검수 기준은 별도 합의가 필요하다.

## 13. 완료 기준 [제안]

- P0로 합의한 검색→상세→인증→신청 흐름과 성공·실패·세션 만료 상태가 검증된다.
- 운영 정책이 필요한 항목은 결정 기록으로 남기고, 화면과 서버 판정이 일치한다.
- 모바일 미설계 화면의 사양을 확정하고 지원 폭에서 주요 과업 수행을 검증한다.
- 콘텐츠 불일치·예시 날짜를 정리하고 실제 데이터 연동의 정확성을 확인한다.
- 개인정보·접근성·성능 목표를 합의하고 검수 결과를 기록한다.

# 수원시 도서관 반응형 웹 서비스

수원시 도서관의 모바일·데스크톱 웹 서비스. 요구사항 원문은 [prd.md](prd.md)이며, 이 문서와 다르면 prd.md를 따르되 기술 스택은 이 문서를 따른다.

## 사용자

### 만드는 사람

이 서비스는 코딩 초보자가 만든다.

- 쉬운 말로 설명하고, 전문 용어를 쓸 때는 뜻을 함께 적는다.
- 무엇을 왜 바꿨는지, 결과를 어떻게 확인하는지 알려준다.
- 한 번에 작은 단위로 변경하고, 요청하지 않은 기능이나 구조 변경을 더하지 않는다.

### 서비스 이용자

| 사용자           | 주요 과업                                          |
| ---------------- | -------------------------------------------------- |
| 비로그인 방문자  | 자료 검색, 도서 탐색, 로그인·회원가입 진입         |
| 회원             | 소장정보 확인, 이용 자격에 따른 예약·상호대차 신청 |
| 방문 예정 이용자 | 도서관 선택, 휴관일·자료 위치 확인                 |

회원과 정회원의 권한 차이, 신청 가능 등급은 정해지지 않았다.

## 기술 스택 (변경 금지)

- React + Vite + JavaScript + 기본 CSS.
- TypeScript, CSS 프레임워크(Tailwind 등), CSS-in-JS, UI 라이브러리로 바꾸거나 추가하지 않는다.
- 다른 패키지가 필요해 보이면 설치하기 전에 이유를 설명하고 먼저 묻는다.
- 프로젝트 루트에서 `npm run dev`(개발 서버), `npm run build`(빌드), `npm run lint`(코드 검사), `npm run preview`(빌드 결과 확인)를 실행한다. 테스트 도구는 아직 없다.

## 디자인 규칙

- 디자인은 추후 Figma MCP를 통해 구현한다. Figma 링크를 받기 전에 화면 디자인을 임의로 만들지 않는다.
- 색상, 폰트, 간격, 라운드, 그림자는 `src/styles/tokens.css`의 변수만 사용한다. 값을 직접 쓰는 하드코딩은 금지한다.
- 새 값이 필요하면 임의로 만들지 말고 먼저 물어본다.
- 컴포넌트는 `src/components/` 아래 폴더별로 만든다.
- 구현 후에는 반드시 Figma와 비교해서 다른 부분을 보고한다.
- Figma에서 읽지 못한 정보는 추측하지 말고 질문한다.
- 반응형은 [prd.md](prd.md)의 브레이크포인트 기준을 따르며, 사이즈별 Figma 링크를 받은 뒤에 구현한다.
- 분기점: 모바일 1023px 이하, 데스크톱 1024px 이상.
- 모바일 우선으로 작성하고 `min-width` 미디어쿼리를 사용한다. 기본 스타일이 모바일, `@media (min-width: 1024px)`가 데스크톱이다.
- 레이아웃은 Flexbox/Grid와 상대 단위(rem, %)를 사용하고, 고정 px 너비는 지양한다.
- 전역 가로 넘침이 없어야 한다. 시안 폭(데스크톱 1440, 모바일 738)은 관측값이며 분기점이나 고정 폭으로 쓰지 않는다.
- 접근성은 WCAG 2.2 AA 수준을 목표로 협의한다.
  - 입력 레이블과 아이콘 버튼(검색·햄버거·닫기·화살표)의 접근 가능한 이름을 제공한다.
  - 키보드 탐색과 가시적 포커스를 제공하고, 모달 종료 시 포커스를 되돌린다.
  - 색상만으로 대출 상태·선택 상태를 구분하지 않는다.

## 서비스 구조

### 코드

- `src/main.jsx`, `src/App.jsx`: 앱 시작점과 최상위 컴포넌트.
- `src/index.css`, `src/App.css`: 전역 스타일과 App 스타일.
- `src/styles/tokens.css`: 디자인 토큰(색상, 폰트, 간격, 라운드, 그림자) 변수.
- `src/components/<컴포넌트명>/`: 컴포넌트별 폴더.
- `src/assets/icons/`: Figma에서 내려받은 아이콘. `mobile/`, `desktop/`, `common/`(공용), `hero/`(모바일 홈 메뉴)로 나눈다.
- `src/assets/images/`: 일러스트와 배경 이미지.
- `src/assets/covers/`: 시안의 예시 책표지. 실제 표지는 데이터로 받으며, `placeholder.jpg`만 표지 없음 이미지로 쓴다.
- `src/assets/sample/`, `src/data/sampleData.js`: 화면 확인용 예시 이미지와 데이터. 백엔드가 정해지면 교체한다.
- `src/App.jsx`: 주소의 `#` 뒤 값으로 화면을 고른다. `#/` 홈, `#/search` 검색, `#/book/아이디` 상세.
- `src/components/ComponentPreview/`: 컴포넌트 확인용 임시 화면(`#/preview`). 필요 없어지면 제거한다.

### 화면 범위

- 홈: 검색, 서비스 바로가기, 인기도서, 신착도서, 휴관일, 추천도서, 공통 푸터.
- 자료검색: 일반검색/상세검색 탭, 도서관 선택, 자료 유형별 결과.
- 로그인 모달, 도서 상세, 소장정보·신청, 상호대차 완료 알림.
- 큐레이션, 전자도서관, 나의도서관 등 링크만 확인된 항목의 상세 화면은 범위에 포함하지 않는다. 전체 목록은 prd.md 4장을 참고한다.

### 핵심 흐름

아래 흐름은 시안을 토대로 정리한 제안이며 실제 동작을 확인한 결과가 아니다.

- 검색: 홈 → 도서관 선택·검색어 입력 → 자료검색 결과 → 도서 상세 → 소장정보 확인.
- 비로그인 신청: 예약/로그인필요 → 로그인 모달 → 인증 성공 → 기존 검색 맥락 복원 → 사용자가 신청 의사를 다시 확인.
- 상호대차: 도서 상세 → 소장도서관별 신청 → 자격·자료 상태 재확인 → 서버 처리 성공 → 완료 알림 → 도서 상세 유지.

### 데이터

- 백엔드와 API는 정해지지 않았다. 논리 데이터 모델은 prd.md 8장을 참고한다.
- 서지와 개별 소장자료를 분리하고, 동일 제목의 다른 저자·판본을 구분한다.
- 검색어와 도서관 조건은 결과 화면에 전달하고, 목록 복귀나 모달 종료 시 유지한다.

## 안전 규칙

### 질문 먼저

- 모르거나 애매한 부분은 추측하지 말고 사용자에게 질문한다.
- PRD의 **[미정]** 항목은 임의로 정하지 않고 질문한다. 정책, API, 상세검색 필드, 탭 본문, 신청 입력 단계 등이 해당한다.
- PRD의 **[제안]** 은 승인 전 확정 정책이 아니고, **[확인]** 은 시안에서 확인한 내용일 뿐 실제 동작을 검증한 것이 아니다.
- 파일·폴더 삭제처럼 되돌리기 어려운 작업은 먼저 확인한다.

### 인증·신청

- 인증 성공만으로 예약·상호대차를 자동 제출하지 않는다.
- 완료 알림은 서버 성공 응답 이후에만 표시하고, 실패 시 완료 문구를 노출하지 않는다.
- 처리 중 반복 제출을 막아 동일 신청의 중복 생성을 방지한다.
- 신청 가능 여부는 회원 자격과 소장자료의 최신 서버 상태로 판단한다. 캐시된 상태를 최종 근거로 쓰지 않는다.
- 인증과 자격 검사는 서버에서 수행한다. 화면 코드의 검사만으로 보호된다고 보지 않는다.
- 비밀번호 등 인증 정보를 표시하거나 로그에 남기지 않는다.

### 시안을 정책으로 오해하지 않기

- 휴관일 2026.09, 반납예정일, 추석 배너의 날짜는 예시값이므로 상수로 구현하지 않는다.
- 예약자수 1/2, 1/1 등을 보고 정원을 2명으로 고정하지 않는다.
- 회색 버튼 표현만으로 활성/비활성 정책을 결정하지 않는다.
- 검색 화면 간 대출 상태 표시 차이만으로 회원 전용 공개라고 단정하지 않는다.
- 정회원신청 표시만으로 로그인 상태나 자격을 단정하지 않는다.
- “오은영의 화해”에 들어간 “여행자 - 하이델베르크” 소개는 시안 오류이므로 그대로 옮기지 않는다.

### 오류 표시

- 결과 없음, 조회 실패, 로딩 상태를 구분한다.
- 휴관일 데이터가 없으면 확인 불가로 알리고 정상 개관으로 오인하게 하지 않는다.
